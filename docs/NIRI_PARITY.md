# Niri parity checklist

Item statuses date from 2026-10-26 unless marked otherwise; refreshed 2026-11-07. Reference: **Niri v26.04**, commit `8ed0da44d974c32c6877d2f4630c314da0717ecb`. Shoji target: macOS 27.2 (26B123). Implement matching behavior independently; retain MIT. This checklist concerns the experience, not replacement of the operating system's compositor.

Checked items mean the stated contract is implemented and has evidence. They do not certify every Niri edge case or application. Unchecked items include partial implementations; each needs its acceptance condition before being checked. Evidence at the last status review: 247 deterministic tests (437 as of 2026-11-07), 70 owned-window native bounds checks, and user acceptance of the basic scrolling motion. A separate-process constrained AppKit fixture also passed native AX sizing and coordinated resize checks; The user confirmed the Chrome/Ghostty three-window, resizing, rapid-change, gesture and close checks work. They report rough motion across these cases, especially smoothness; quantitative frame pacing and latency remain open. [Implementation and commands](SCROLL_LAYOUT.md), validation, pinned interaction reference.

## Core behavior already implemented

- [x] **C01 — Stable horizontal columns.** Opening additional windows retains existing widths and inserts beside the active column. Three/four-column fixtures cover the default geometry.
- [x] **C02 — Shared camera movement.** Columns translate together through a stationary viewport, with a critical spring and continuous retargeting. Visible spacing is checked during sampled native movement.
- [x] **C03 — Keyboard focus and centering controls.** Minimal reveal, explicit centering, Never/Always/OnOverflow options and immediate logical focus exist. Full edge-case parity remains P03 below.
- [x] **C04 — Offered gesture's core release behavior.** Fn plus two-finger horizontal panning, timestamped velocity, predicted snap, directional focus selection and spring settling exist. Five pinned release fixtures pass. This is not unmodified three-finger input.
- [x] **C05 — Column and row sizing controls.** Pixel/proportional column requests, width/height presets, full-width restoration, fixed/weighted rows and rounded allocation exist. Basic Chrome/Ghostty sizing works in user acceptance; broader sizing coverage remains P01.
- [x] **C06 — Column membership actions.** Consume, expel, directional consume/expel, row navigation, column movement and width-preserving warp exist. Legacy and directional expel preserve different focus policies. Rows retain Shoji's existing 32-member limit.
- [x] **C07 — Stationary pointer policy.** Scroll layout does not warp the pointer by default; explicit overrides remain available. Pointer-driven focus is gated during camera movement.

## Recommended implementation sequence

1. P01/P02/P07: prioritize motion smoothness following basic Chrome/Ghostty acceptance. Measure frame pacing, input latency and AX write cost; align presentation scheduling with display refresh where supported. Investigate B01/B02/B03 in parallel because they determine the presentation ceiling.
2. P04/W02/W03: visible focus, insertion feedback and edge-assisted dragging. These directly improve everyday manipulation without waiting for a new workspace model.
3. W04/B02: complete tabs, with truthful concealment guarantees.
4. W05/W06: choose and implement opt-in dynamic workspace behavior while retaining existing native Space recovery.
5. W07/W08: overview navigation, then rearrangement.
6. W09/W10 and P2: broader input/output coverage and customization, informed by validated platform capabilities.

Cross-cutting Shoji quality gates: restore ordinary native windows on interruption/exit, preserve usable focus and dialog layering, avoid Accessibility reauthorization on updates, and retain an exact rollback binary. These are operational requirements for this macOS implementation, not additional Niri feature claims. Native Spaces continue to use their current backend/security prerequisites. A complete Wayland compositor, launcher, bar, notification service and lock screen are separate components; existing macOS services remain integration choices. [Niri companion software](https://github.com/niri-wm/niri/blob/8ed0da44d974c32c6877d2f4630c314da0717ecb/docs/wiki/Important-Software.md).

Shoji's Fn-assisted BSP Space wraparound is an implemented user-requested extension. It is not evidence for Niri's dynamic workspace model or native three-finger input.

Resize presentation update (2026-10-27): content blending mixes the old snapshot with the live app using geometry progress, completing with the resize. Long manual drags retain a pixel-derived application background fallback. This is a native presentation adaptation; visual acceptance and compositor parity remain open.
