# Presentation signals and candidate coordination paths

Research date: 2026-10-28. This is a primary-source and existing-code review, not a new proof of frame-atomic foreign-window control. Local target: macOS 15.6 (24G84); private behavior must be revalidated by build.

## Signals

| Signal | What it means | Limit for Shoji |
| --- | --- | --- |
| `CADisplayLink.targetTimestamp` | Apple describes a predicted time for the next display frame and recommends using it to schedule animation work. [Apple targetTimestamp](https://developer.apple.com/documentation/quartzcore/cadisplaylink/targettimestamp), [AppKit display links](https://developer.apple.com/videos/play/wwdc2023/10054/) | A scheduling deadline, not confirmation that a foreign application's AX movement appeared. Shoji already uses display pacing. |
| AX moved/resized notification | Apple's `kAXMovedNotification` means an accessibility element's position changed; `kAXWindowMovedNotification` is specifically described as sent at the end of a window-move operation. These are distinct notifications. [Apple AX notifications](https://developer.apple.com/documentation/applicationservices/carbon_accessibility/notifications), [AppKit moved](https://developer.apple.com/documentation/appkit/nsaccessibility-swift.struct/notification/moved) | Neither is documented as a per-display-frame compositing acknowledgment. Availability, coalescing and delivery latency can differ per app. Shoji subscribes to `AXMoved`/`AXResized` and marks focused geometry dirty in [the observer](../../../src/backend.odin#L324); general desktop rediscovery is deferred during scroll in [runtime](../../../src/runtime.odin#L125). |
| `SLSGetWindowBounds` | Shoji uses this private readback in `mouse_native_resize_frame` and during scroll ring movement in [input](../../../src/input.odin#L390) and [motion](../../../src/motion.odin#L2195). | Existing fixture observations show readback can still be one motion step behind the model. It is not independently verified displayed pixels or an atomic cross-process frame barrier. |
| ScreenCaptureKit `SCStreamFrameInfo.displayTime` | Apple documents it as the WindowServer display time for a frame. The local SDK `SCStream.h` specifies Mach absolute time. Apple demonstrates retrieving frame metadata from sample-buffer attachments and checking `SCFrameStatus.complete`. [Apple displayTime](https://developer.apple.com/documentation/screencapturekit/scstreamframeinfo/displaytime), [Apple capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) | Better frame attribution than the harness's delivery callback uptime. It is capture metadata after the fact, not a mechanism to commit foreign windows and the ring together; filtered capture can omit frames and is not independently established physical scanout or photon time. Record raw value, frame status, callback time and explicit Mach timebase conversion; validate clock correlation empirically before calculating latencies. |
| `MTLDrawable.addPresentedHandler` and `presentedTime` | Apple documents a callback and host time for a drawable the caller presents; dropped/not-yet-presented drawable time is zero. [Apple handler](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler(_:)), [Apple presentedTime](https://developer.apple.com/documentation/metal/mtldrawable/presentedtime) | May instrument or schedule a Shoji-owned Metal drawable. It does not provide a foreign app's drawable or presentation callback, and current native focus ring uses separate WindowServer surfaces rather than a Metal drawable. |

## Transaction candidate

The locally observed SkyLight export `SLSTransactionSetWindowTransform` was observed in SkyLight's exports. Yabai's [declarations](https://github.com/asmvik/yabai/blob/master/src/misc/extern.h) specify a transaction, window ID, two unknown integers and affine transform; its [animation loop](https://github.com/asmvik/yabai/blob/master/src/window_manager.c) batches transforms of its own proxy window IDs and commits the transaction. This is a relevant implementation example for coordinated proxy presentation, not a verified current ABI, return contract, permission to transform foreign native windows, or proof that input follows the visual transform. Shoji's [transaction ABI investigation](../../../docs/TRANSACTION_ABI.md) demonstrates that apparent return values in upstream declarations can be misleading on 24G84.

Recommended next discriminating test: in an isolated, PID-scoped fixture, validate transaction-transform ABI and visual behavior on two controller-owned surfaces first; next separately test foreign fixture windows without and with an explicitly identified privileged context. Log independently observed pixels, readback and hit tests, and verify restoration. Do not invoke unverified signatures inside WindowServer or interpret a void/ambiguous return register as success. Whether transforming foreign windows also transforms hit testing, shadows and accessibility geometry remains open. SLS transaction grouping must not be equated with physical scanout atomicity without frame evidence.

## Measurement improvement

Extend the existing capture harness to log the attachment's raw display time, status, callback time and timebase; correlate with separately timestamped controller events and capture only complete frames. Compare against current callback-time analysis and quantify dropped, missing, malformed or out-of-order metadata. A positive-control moving marker and static control should validate that the display-time sequence and converted clock agree within measured uncertainty. Treat this as an observability improvement, not a production synchronization solution. Source review alone does not establish a documented public signal providing atomic presentation of another process's AX-set geometry alongside Shoji-owned decorations.
